# 实施路线

原则：先让检索、身份核验、出版后状态和审计成为确定性内核，再让 AI 消费
已通过明确门槛的数据。任何阶段都不得把软件自检、AI 模拟或匿名自我声明
冒充外部人工审核。

## 当前基线：v0.3 可审计开放文献检索内核

已实现并有测试覆盖：

- PubMed 与 Europe PMC 发现、显式截断和完整分页状态；
- PubMed History Server（`WebEnv/query_key`）固定本次 UID 集，Europe PMC
  cursor 分页；
- Crossref DOI/题名核验，DOI/PMID/题名去重和冲突阻断；
- Crossref 反向更新与 PubMed `CommentsCorrections` 撤稿、更正、关注表达式
  关系进入 `citation_ready` 门控；查询不完整时失败关闭；
- 脱敏原始响应、输出 SHA-256、manifest/record JSON Schema 和运行校验；
- SQLite 内容寻址 HTTP 缓存、blob 哈希复核、WAL/事务，以及严格离线回放；
- 题名、DOI、PMID 的字段级选择依据、备选观察值和 evidence ID 溯源基础；
- 版本关系图的数据结构、证据必填与环检测，但尚未自动生成；
- 未经身份验证的核读自我声明、撤销和事件哈希链；
- 6 例 golden seed 与关键假阳性阻断规则。
- 安全全文下载器、许可证候选提取、Crossref fallback 状态适配、受限
  claim–evidence 位置绑定和外部 Ed25519 核读请求包；
- 240 条明确非人工黄金的确定性合成契约/对抗用例。

2026-07-26 v0.3 集成验收批次：87 项测试通过；同一真实查询的在线捕获与严格离线回放
生成了 SHA-256 相同的 `records.jsonl`。这证明本轮缓存输入下的确定性重放，
不证明远端数据永久固定，也不证明完整系统综述覆盖。
v0.3.1 本轮本地集成测试为 155 项并全部通过；87 项仍保留为历史批次计数。

当前产物仍只能进入“引用候选池”，不能自动进入综述正文。

## 下一阶段 A：检索恢复与规模化可靠性

1. 将 append-only attempt/checkpoint 与分页执行接通，实现中断续传和部分页恢复；
2. 增加检索批次比较，显式报告新增、消失和字段变化；
3. 扩大到至少 200 例黄金集，纳入真实撤稿、更正、关注表达式、标识符错配、
   缓存缺失、部分 API 失败和跨版本重复等困难样本；
4. 增加长期真实 API 回归样本，并区分远端漂移与软件回归；
5. 继续验证超大 History 集、服务端会话过期和缓存不完整场景。

240 条合成用例已补足软件契约规模门，但同类模板变体不是独立真实情境。
至少 200 例真实困难样本与外部人工裁决仍未完成。

## 下一阶段 B：合法全文取得

1. 从 PMC/Europe PMC OA、Unpaywall 等合法来源自动发现候选全文位置和版本；
2. 对逐篇许可证、稿件版本和用途做保守判断；未知、冲突或限制性条款失败关闭；
3. 实现独立的安全全文下载器，包含 DNS/IP、私网与重绑定防护、重定向重验、
   响应大小、内容类型、文件签名和压缩包边界；
4. 保存取得来源、许可证原文/标识、材料 SHA-256、取得时间和版本关系；
5. 在现有 Crossref fallback 之外接入有明确契约的独立实时 Crossmark 提供方。

本阶段的安全下载器和元数据候选提取已实现；未知/歧义许可证、跨源重定向和
不安全网络均失败关闭。尚缺可控公网环境的真实下载验收、许可证证据结构化绑定、
更广发布商格式与最终法律意见。

## 下一阶段 C：证据与版本生产化

1. 把字段级 provenance 扩展到作者、期刊、年份、全文位置、许可证和出版后状态；
2. 自动提出预印本、接受稿、正式版、更正稿、撤稿通知之间的版本边；
3. 对自动版本边保留来源证据、置信边界和人工裁决队列；
4. 建立 claim–evidence 绑定：每个综述陈述必须指向具体材料、页码/段落/表图和
   材料哈希；
5. 未完成全文核读和 claim–evidence 核验时，不允许产生 `claim_verified` 或
   `synthesis_ready`。

UTF-8 文本和 article XML 的 quote/paragraph 绑定已实现，且文本由材料内部
确定性派生。PDF/OCR/page/section/table/figure 的受控提取链仍未实现；当前版本图
也尚未接入检索流水线自动生产。

## 下一阶段 D：外部人工治理

- 引入真实外部核读者的受控身份、同意、角色/资历和审批证据；
- 在需要匿名时，公开层只显示匿名角色，身份映射保存在受控系统；
- 区分自我声明、身份已验证、全文已核读、分歧已裁决和允许发布；
- 撤销通过追加事件完成，不覆盖历史。

当前 `HUMAN_READ_SELF_ATTESTED` 明确为 `identity_verified=false`，只证明
声明事件及材料指纹进入了哈希链；它不证明操作者身份或实际核读事实。
外部 Ed25519 签名包同样只证明给定密钥控制，不证明现实身份或实际核读。

## 后续：跨学科扩检与 AI 智能体层

- OpenAlex 用于跨学科发现、引用链和作者/机构图谱；
- Zotero CSL JSON/BibTeX/RIS 导出；
- PRISMA 去重、纳排决定、排除理由和人工审核队列；
- 对商业数据库合法导出的 RIS/CSV 做本地合并，以机构访问补齐覆盖。

AI 只能读取结构化、带证据状态的记录：

1. Literature Scout：提出候选，不升级证据状态；
2. Citation Checker：核对引用与书目记录，不判断研究结论；
3. Evidence Grader：在取得合法全文后给出可复核评价；
4. Mechanism Mapper：每条边绑定材料位置与证据；
5. Review Writer：只引用通过指定门槛的记录；
6. Devil's Advocate：主动检索反证与覆盖缺口。

任何 LLM 输出都不能把状态直接升级为外部人工已核读、`claim_verified` 或
`synthesis_ready`。
