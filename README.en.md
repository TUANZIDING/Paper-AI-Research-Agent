Paper AI Research Agent is a local, auditable literature-evidence tool built on
open scholarly APIs. It separates discovery (including citation snowballing to
saturation), bibliographic verification, post-publication status checks, lawful
full-text access, evidence-location binding, and human gates into verifiable,
fail-closed stages.

> [!IMPORTANT]
> This project does not bypass paywalls, authentication, robots.txt rules, or
> institutional access. It is not equivalent to Embase, Scopus, or Web of Science.
> `citation_ready=true` does not mean that a paper has been read, that its conclusions
> are reliable, or that a systematic-review search is complete.

## Overall workflow

<p align="center">
  <img src="docs/assets/workflow-v0.4.svg" width="100%" alt="Overall workflow: four entry points (topic search, existing PDF, single DOI, official source) flowing through discovery, identity verification, post-publication gate, lawful full text, claim–evidence binding and human gates, with an evidence-status ladder and the audit foundation (labels in Chinese)">
</p>

Four entry points (topic search, an existing PDF, a single DOI, an official source) feed one evidence chain: **discovery → identity verification → post-publication gate → `citation_ready` → lawful full text → claim–evidence location binding → human gates**. Every step up has its own command and fail-closed condition; `claim_verified` / `synthesis_ready` are never produced by software.

| Layer | Command | Core modules |
|---|---|---|
| Discovery and verification | `search` | `sources.py` · `pipeline.py` · `publication_status.py` |
| Single-DOI post-publication status | `check-status` · `check-crossmark` | `publication_status.py` · `crossmark.py` |
| Exhaustive-as-feasible retrieval | `exhaustive` | `exhaustivev04.py` · `snowballv04.py` · `openalexv04.py` · `crossrefsearchv04.py` · `europepmcgraphv04.py` |
| Lawful full text | `exhaustive` (OA triage) · `download-fulltext` · `discover-licenses` | `openaccessv04.py` · `fulltext.py` · `license_policy.py` |
| Institutional access (yourself) | `institution-links --open-login` | `institutionv04.py` |
| Evidence and replay | `verify-run` · `--cache-db --offline-replay` | `archive.py` · `cache.py` · `replay.py` |
| Exports | generated by `exhaustive` | `exportv04.py` (RIS / BibTeX / ASReview CSV / PRISMA) |
| PDF reverse audit | `audit-pdf-references` | `pdf_audit.py` · `reference_batch.py` |
| Official-source candidates | `register-official-source` · `propose-official-source` | `official_sources.py` |
| Evidence binding | `bind-claim` | `claim_evidence.py` |
| Human gates | `attest-read` · `rescind-read` · `verify-read-log` · `prepare-review-packet` · `verify-review-signature` | `human_read.py` · `external_review.py` |
| Reliability evaluation | test suite | `evaluation.py` (golden seeds + 240 synthetic cases) |

## v0.4 exhaustive-as-feasible retrieval (`exhaustive`)

```bash
export RESEARCH_AGENT_EMAIL="your contact email"  # needed for Unpaywall; env only, never archived
export OPENALEX_API_KEY="optional"                 # without a key OpenAlex may return HTTP 429, logged as a source issue, not 0 hits
research-agent exhaustive '<PubMed Boolean query>' \
  --source-query 'europe_pmc=<Europe PMC query>' \
  --source-query 'openalex=radiation-induced skeletal muscle injury' \
  --require 'radiat*|irradiat*|radiotherap*' \
  --require 'muscle*|myopath*|myoblast*' \
  --all --max-seeds 30 --max-rounds 3 --output runs
```

Boundaries:
- Each round logs the frontier, backward/forward links, new unique candidates, new relevant records, truncation and errors; reaching the round cap with new records still appearing is marked **NOT saturated**.
- **Saturation is not a complete systematic-review search**: Embase, Scopus, Web of Science, Chinese databases, grey literature and human screening are still required.
- Only CC BY / CC BY-SA / CC0 / public-domain open full text is downloaded; everything else goes to an institutional-access list (institutional access, interlibrary loan, or contacting authors). No paywall, login, or robots bypass.
- Exclusion rule: `--exclude 'low-level laser|photobiomodulation'` drops obvious false hits (e.g. low-level laser), while `--exclude-unless 'ionizing|radiotherap*'` keeps records that also mention ionizing radiation or radiotherapy; dropped records are tagged `exclusion_rule` in `auto-excluded-v0.4.csv` and counted in the report.
- Per-round candidate cap: `--max-candidates-per-round` (default 5000); a round exceeding it is truncated and logged. Raise it (e.g. 10000) for large topics.
- The ASReview `included` column is left blank for human decisions. Semantic Scholar is not yet integrated.

### Institutional access (for your own account only)

The `needs-institutional-access` list can be turned into a manual checklist, `institutional-access-v0.4.html`, using **your own institution's** access profile: each record gets the publisher platform's CARSI/Shibboleth federated-login entry and its DOI link; unmatched records fall back to WebVPN or interlibrary loan.

```bash
cp profiles/institution-profile-example-v0.4.json ~/.config/research-agent/my-institution-v0.4.json  # fill in the entry links your library publishes
export RESEARCH_AGENT_INSTITUTION_PROFILE=~/.config/research-agent/my-institution-v0.4.json
research-agent exhaustive '...' --require '...'            # applied automatically
research-agent institution-links runs/exhaustive-...        # or rebuild for an existing run
```

- Long runs can resume: add `--cache-db runs/cache.sqlite --resume` and re-run the same command; cached responses are reused and only missing ones are fetched.
- Personal use: `research-agent institution-links <run dir> --open-login` pops up the needed platforms' institutional sign-in pages (CARSI/WebVPN) in your own browser; you type your credentials on your institution's page and the tool never touches them. `--open-articles N` then opens articles one at a time (Enter per article, max 20).
- A profile holds **no usernames, passwords, cookies or tokens**; such fields are rejected. Keep it outside the repository; its path is not written to the manifest.
- The tool **never logs in, stores sessions, or downloads through institutional access**. The entitled person opens each article (Zotero Connector works well); library licences generally forbid software-driven bulk downloading.
- Anyone else using this project supplies a profile for **the institution that licenses them**; the repository ships only a generic example.

## Capability status

| Status | Capability | Exact boundary |
|---|---|---|
| Implemented | PubMed and Europe PMC retrieval with pagination state | Explicitly reports `complete`, `truncated`, or `partial` |
| Implemented | DOI/PMID/title deduplication and NCBI/Crossref verification | Metadata conflicts fail closed |
| Implemented | Crossref and PubMed post-publication gate | Risk signals or incomplete checks block citation candidates |
| Implemented | Raw-response archive, `evidence_id`, SHA-256, and `verify-run` | Checks files against the current manifest |
| Implemented | Content-addressed SQLite cache and strict offline replay | Missing cache entries never fall back to the network |
| Implemented (v0.4) | OpenAlex and Crossref as extra sources; forward/backward citation snowballing | Ranked sources are top-N and merge into the same DOI/PMID deduplication |
| Implemented (v0.4) | Saturation curve, stop reason, per-round candidate cap, exclude/rescue terms | Saturation means ≈0 new records under current sources and rules, not systematic-review completeness |
| Implemented (v0.4) | RIS, BibTeX, ASReview CSV, PRISMA counts; `--resume` from cache | Exports still require human screening |
| Limited (v0.4) | Institutional-access checklist and `institution-links --open-login` | Opens the login page in your own browser only; never touches credentials or auto-downloads |
| Limited | Numbered-PDF reference extraction and body-citation location mapping | Requires a heading and continuous `[1]..[n]`; location is not semantic support |
| Limited | Resumable PDF-reference lookup batches | Completed items are skipped while unfinished/partial/failed items remain retryable; not general pagination resume |
| Limited | Manually registered official-organization host/path candidates | An explicit allowlist and hashed registration evidence produce candidates only; no official-identity proof or fetch permission |
| Limited | License/location candidates and policy-gated public full-text fetcher | A candidate is not legal clearance; explicit license, version, and all safety gates are required |
| Limited | Crossref status fallback | `crossmark_realtime_verified=false`; not a live Crossmark verification |
| Limited | Quote/paragraph binding in hashed UTF-8 or JATS text | A location match is not semantic support or `claim_verified` |
| External gate required | Real identity, actual human reading, and final legal approval | Ed25519 proves control of the supplied key only |
| External gate required | 200+ independently human-adjudicated gold cases | The current 240 cases are synthetic contract/adversarial cases with `human_adjudicated=false` |

## Quick start

Python 3.10+ is required. The network/audit core uses the standard library; PDF text extraction uses `pypdf`, installed with the project.

```bash
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -e .

research-agent search '"diabetic osteoporosis" AND osteoblast' --limit 10
```

By default, each search writes to a dedicated, non-overwriting run directory containing:

```text
runs/<UTC-time>-<query>/
├── manifest.json
├── records.jsonl
├── report.md
└── raw_responses/
```

Verify a run:

```bash
research-agent verify-run /absolute/path/to/run-directory
```

Reverse-audit a local PDF (local extraction only by default):

```bash
research-agent audit-pdf-references /absolute/path/to/article.pdf \
  --output /absolute/path/to/pdf-audits

# Network lookup is explicit; raw PubMed/Europe PMC responses are archived
research-agent audit-pdf-references /absolute/path/to/article.pdf \
  --lookup --cache-db /absolute/path/to/http-cache.sqlite3 \
  --output /absolute/path/to/pdf-audits

# A bounded live lookup can target difficult entries first
research-agent audit-pdf-references /absolute/path/to/article.pdf \
  --lookup --lookup-references 1,46,59 --limit-per-reference 5

# Process at most 10 unfinished items now; reuse the checkpoint to continue
research-agent audit-pdf-references /absolute/path/to/article.pdf \
  --lookup --lookup-references 1-75 --max-items 10 \
  --checkpoint /absolute/path/to/reference-checkpoint.jsonl \
  --cache-db /absolute/path/to/http-cache.sqlite3
```

The checkpoint is an append-only, hash-chained progress ledger bound to selected
references and their input payloads. Tampering, truncation, or reuse with different
inputs fails closed. It resumes per-reference lookups only, not PDF extraction or
interrupted pagination in the general `search` command.
If a batch remains `partial`, `failed`, or `pending`, the command preserves its
artifacts and exits with status 3. It exits 0 only when all selected lookup chains
are `completed`.

Artifacts bind the PDF hash to parsed references, page/context citation locations,
candidate scores, raw API bytes, and a manifest. Automated output retains
`semantic_support_status=NOT_ASSESSED` and `human_adjudicated=false`; see the
[PDF reference-audit boundary](docs/PDF_REFERENCE_AUDIT.md).

Strict offline replay:

```bash
research-agent search 'YOUR QUERY' --limit 10 \
  --cache-db /absolute/path/to/http-cache.sqlite3 \
  --output /absolute/path/to/online-runs

research-agent search 'YOUR QUERY' --limit 10 \
  --cache-db /absolute/path/to/http-cache.sqlite3 \
  --offline-replay \
  --output /absolute/path/to/replay-runs
```

License-candidate discovery and policy-gated full text:

```bash
research-agent discover-licenses --crossref /absolute/path/to/crossref.json

research-agent download-fulltext \
  --url 'https://repository.example/article.xml' \
  --license 'CC BY 4.0' \
  --version publishedVersion \
  --output /absolute/path/to/article.xml
```

The fetcher checks a conservative license allowlist, manuscript version, HTTPS,
DNS/IP and SSRF constraints, same-origin redirects, robots policy, wall-clock timeout,
size, PDF/JATS XML structure, and atomic persistence. PDF validation also requires
local `pdfinfo`. Any failed gate stops the operation.

Register an official-source candidate (no network request or fetch permission):

```bash
research-agent register-official-source \
  --organization-id example-guideline-body \
  --organization-name 'Example Guideline Body' \
  --hostname guidance.example.org --path-prefix /standards \
  --registrar-role 'information governance reviewer' \
  --evidence-source-url 'https://registry.example.org/entry' \
  --evidence-file /absolute/path/to/registry-evidence.txt \
  --observed-at '2026-07-27T10:00:00+08:00' \
  --output /absolute/path/to/official-source-evidence

research-agent propose-official-source \
  --registration-bundle /absolute/path/to/official-registration-SHA256.json \
  --organization-id example-guideline-body \
  --url 'https://guidance.example.org/standards/item' --title 'Guideline title' \
  --output /absolute/path/to/official-source-evidence
```

## Trust model

- Abstracts, full text, webpages, attachments, and remote metadata remain untrusted inputs.
- `citation_ready` means eligible for human screening—nothing more.
- `unknown` is never rewritten as safe or not retracted.
- License discovery produces candidates, not final legal opinions.
- A claim location does not prove scientific truth or semantic entailment.
- A self-attestation hash chain does not prove identity; a signature proves key control only.
- Coverage from open scholarly sources is not equivalent to commercial-database coverage or a complete systematic-review search.
- A webpage cannot promote itself by claiming to be official. An official-source
  candidate does not prove domain control, currentness, legal permission, or human
  reading, and currently retains `network_fetch_permitted=false`.
